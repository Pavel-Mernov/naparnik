# 07. Требования к фронтенду

> Фреймворк выбирает команда; оценивается совместимость со стеком Авито (React + TypeScript, TanStack, Zustand, Zod). Бэкенд — Go.
> Требования описывают **что** должно быть на экранах и **как себя вести**, а не как верстать. Визуал и маскот — в [08-DESIGN.md](./08-DESIGN.md).

## 1. Общие требования

| ID | Требование |
|---|---|
| FE-01 | Одно веб-приложение, интерфейс зависит от роли текущего пользователя (02-ROLES) |
| FE-02 | Переключатель тестовых учёток в шапке для демо; скрывается feature flag `demo_role_switcher` |
| FE-03 | Явный API-клиент с типизированными контрактами (схемы валидации ответов, например Zod) |
| FE-04 | Статусы вопросов, заявок и уведомления обновляются без перезагрузки (WebSocket или SSE) |
| FE-05 | Локальные операции (отметить шаг, открыть карточку, фильтр) — отклик < 1 с; оптимистичное обновление с откатом при ошибке (BR-71) |
| FE-06 | Запросы к LLM и сервисам не блокируют интерфейс: статус «думаю…», таймаут 30 с, ошибка с «повторить», ввод не теряется; в упрощённом режиме — пометка «Упрощённый режим · без модели» и кнопки быстрых действий под последним ответом (BR-70) |
| FE-07 | Светлая и тёмная тема на токенах; адаптив от 1280 px (основной сценарий — ноутбук), корректно до 360 px |
| FE-08 | Доступность: управление с клавиатуры, видимый фокус, подписи к иконкам, контраст по WCAG AA, `prefers-reduced-motion` |
| FE-09 | Синтетические инструкции помечены бейджем «Тестовая инструкция» (BR-05) |
| FE-10 | Недоступное по правам не рендерится и не запрашивается; при прямом переходе по ссылке — экран «Нет доступа» без деталей объекта (BR-40) |
| FE-11 | Каждое действие пользователя отправляет событие аналитики (09-METRICS) |

## 2. Общий каркас

- **Шапка:** логотип, навигация по разделам роли, колокольчик уведомлений со счётчиком, профиль (настройки, Telegram), переключатель учётки (демо).
- **Маскот-виджет** — у стажёра на всех экранах; у остальных ролей не показывается в MVP.
- **Панель чата** — выезжает справа по клику на маскота; не перекрывает основной контент на ширине ≥ 1440 px, на меньших — поверх с затемнением.
- **Центр уведомлений** — список по клику на колокольчик: тип, текст, время, ссылка на объект, «прочитать всё».

## 3. Экраны стажёра

### SCR-I1. Главная («Мой день»)
| Блок | Содержание | Действия |
|---|---|---|
| Шаги на сегодня | 1–3 шага: название, этап, срок, подготовленное действие (например «черновик готов») | Отметить выполненным; открыть; «нужна помощь» → чат |
| События | Сегодня и на неделе: встречи, мастер-классы, дедлайны | Открыть встречу; отложить напоминание |
| Прогресс | Этапы плана, % текущего этапа, просрочки | Перейти в «Мой план» |
| Мои вопросы | 3 последних с статусами | Перейти в «Вопросы» |

Пустое состояние: план ещё не утверждён → «План готовится, пока можно спросить что угодно».

### SCR-I2. Чат (панель маскота)
- Лента сообщений: вопросы стажёра и ответы ИИ.
- Ответ из базы — карточка: текст, источник (название страницы, автор, дата), кнопки «помогло / не помогло / устарело».
- Предложение адресата — карточка: имя, роль, **причина выбора**, кнопки «Да, спроси», «Нет».
- Черновик вопроса — редактируемый текст, переключатель «Срочно», кнопка «Отправить», подпись «уйдёт в сводку в 16:00» или «уйдёт сразу».
- Черновик действия (заявка) — поля, «Подтвердить», «Изменить», «Отмена»; после — квитанция.
- Индикатор «думаю…»; ошибка с «повторить».
- Контекст: если чат открыт со страницы базы или задачи — в шапке чата чип «о странице {название}».

### SCR-I3. Мои вопросы
- Список с фильтрами по статусу. Колонки: вопрос, адресат, статус, срочность, обновлено.
- Карточка вопроса: история (кому отправлен, переадресации, ответы), ссылка на страницу базы, встреча.
- Черновики: «вернуться и отправить».

### SCR-I4. Мой план
- Этапы по неделям, шаги со статусами `Planned / Today / Done / Overdue`.
- Пометка «План не утверждён», если активирован по шаблону.
- Шаг «Познакомься с командой» открывает **карту команды** (SCR-I5).

### SCR-I5. Команда
- Карточки людей: имя, роль, зона ответственности, ссылки на их страницы в базе.
- «Написать» → черновик сообщения для копирования (кнопка «Скопировать»). Отправки от имени ИИ нет (BR-62).

### SCR-I5a. Профиль (карточка сотрудника)
- Фото (круг; без фото — инициалы), ФИО, статус-бейдж («Стажёр», «Бадди», «Эксперт», «Руководитель»), должность, отдел, рабочие телефон и почта (ссылки `tel:` и `mailto:`).
- У стажёра: дата старта, неделя стажировки, бадди и руководитель.
- Своя карточка (`can_edit`): «Загрузить фото» (уменьшить картинку до 512 КБ перед загрузкой), «Убрать фото», правка телефона. ФИО, отдел и почта не редактируются.
- Открывается из меню учётки (своя) и из карточек «Команды», обзора руководителя и плана стажёра у бадди.
- API готов: [spec/05, «Профили сотрудников»](../spec/05-tools-api.md#профили-сотрудников-us-38).
- Сделано: `widgets/profile` (`ProfileDialog`, `ProfileAvatar`) — открывается из меню учётки («Мой профиль») и по имени стажёра у руководителя («Команда») и бадди («Мои стажёры»); своё фото — и в аватаре шапки. На телефоне — во весь экран. Фото больше 512 КБ уменьшается в браузере (до 1024 px, JPEG). Фото грузится с `X-User` и показывается через object URL. Тесты — `ProfileDialog.test.tsx`.

### SCR-I6. База знаний
- Поиск, дерево папок, список страниц: название, автор, дата, тип (статья / вопрос-ответ / со встречи).
- Страница: текст, автор, дата, исходный вопрос, ссылка на запись и таймкоды, бейдж «Тестовая инструкция» при необходимости.
- Только пространство своей команды.

### SCR-I7. Заявки
- Список заявок: тип, даты, статус, номер. Карточка — квитанция и история статусов.

### SCR-I8. Настройки
- Проактивность: «план на день» / «только дедлайны и встречи» / «выкл».
- Видимость для бадди: «показывать текст моих вопросов» (вкл. по умолчанию).
- Рабочие часы, «не беспокоить», интервалы напоминаний.
- Telegram: «Подключить» → одноразовый код и ссылка на бота; статус подключения; «Отключить».
- Маскот: показывать / свернуть / скрыть, анимации вкл/выкл.

## 4. Экраны бадди

### SCR-B1. Мои стажёры
- Карточка на стажёра: этап, % выполнения, просрочки, открытые вопросы, сигналы «застрял» / «простаивает».

### SCR-B2. Лента вопросов стажёра
- Хронология маршрутов: время, тема, адресат, причина выбора адресата, статус, срочность.
- Текст вопроса — если стажёр разрешил; иначе плашка «Стажёр скрыл текст».
- Действие «Переадресовать» → выбор человека из отдела → подтверждение.
- Фильтр «только ошибочные маршруты» (были «не ко мне») — подсказка, где ИИ ошибался.

### SCR-B3. Входящие (вопросы, адресованные бадди)
- Вкладки «Срочные», «Сводка», «Все». Сводки сгруппированы по времени и стажёру.
- Карточка вопроса — общий компонент для бадди, эксперта и руководителя (SCR-E2).

### SCR-B4. Черновики на проверку
- Черновики страниц из ответов бадди: предпросмотр, «Ок», «Править», папка, «дополнить существующую».

### SCR-B5. План стажёра
- Редактирование черновика плана: шаги, сроки, порядок, добавить шаг из шаблона.

### SCR-B6. Моя нагрузка
- Вопросы, ответы, встречи за неделю и месяц; оценка времени.

## 5. Экраны эксперта

### SCR-E1. Входящие
- Как SCR-B3: «Срочные», «Сводка», «Все». Счётчик ожидающих.

### SCR-E2. Карточка вопроса (общий компонент)
| Блок | Содержание |
|---|---|
| Шапка | Тема, стажёр, срочность, SLA («ответить до…») |
| Вопрос | Суть, контекст, что уже пробовал, ссылки |
| Почему вам | Причина выбора адресата. Для вопроса по BR-10a у бадди: «Тема в зоне {имя, роль} из руководства. Ответьте сами или переадресуйте»; кнопки «Не ко мне» нет |
| Действия | «Ответить текстом» (редактор), «Встреча» (3 слота → выбрать), «Не ко мне» (необязательно указать кому) |
| После ответа | Уточнения стажёра в той же карточке |

### SCR-E3. Черновики на проверку
- Как SCR-B4. Для встречи: выжимка, таймкоды, ссылка на запись, «Ок» / «Править».
- Записи нет: вопрос «Записи нет. Сформируем ответ текстом?» — «Да» открывает редактор, «Нет» закрывает.

## 6. Экраны руководителя

### SCR-L1. Дашборд отдела
- Стажёры: этап, %, просрочки, сигналы, статусы заявок.
- Нагрузка: бадди и эксперты — вопросы, ответы, встречи, оценка времени за период.
- Метрики отдела из 09-METRICS: время до первой полезной задачи, доля вопросов, закрытых базой, рост базы.
- Тексты вопросов стажёров не показываются.

### SCR-L2. Планы адаптации
- Черновики на утверждение: «Утвердить», «Вернуть бадди с комментарием». Пометка «не утверждён» у активированных по шаблону.
- Сделано: `widgets/plan-draft` — в «Команде» у стажёра с неутверждённым планом «Утвердить план» (окно со шагами по этапам); у бадди в «Мои стажёры» — «Проверить черновик»: сроки (рабочий день), «Убрать / Вернуть», комментарий руководителю. «Вернуть бадди с комментарием» — следующий шаг.

### SCR-L3. Поддержка базы
- Вкладки: «Открытые вопросы» (назначить адресата), «Черновики без подтверждения», «Отмечено устаревшим», «Дубли».
- Дубли: две страницы рядом, предложенный объединённый текст, «Объединить», «Править», «Не дубль».
- Дата следующей плановой проверки; кнопка «Запустить сейчас» (feature flag, для демо).
- Настройка владельца базы.

## 7. Состояния, которые нужно отрисовать

| Состояние | Где | Поведение |
|---|---|---|
| Загрузка | Все списки и карточки | Скелетоны; без блокировки навигации |
| ИИ думает | Чат, маскот | «Думаю…», маскот в состоянии `thinking` |
| Пусто | Списки | Подсказка, что здесь появится, и действие |
| Ошибка LLM / сервиса | Чат, заявки | Понятный текст, «повторить», данные не потеряны |
| Нет доступа | Прямые ссылки | Экран «Нет доступа» без деталей объекта |
| Офлайн | Глобально | Плашка «Нет соединения», действия в очереди |
| Telegram не подключён | Настройки | Призыв подключить, без навязчивых баннеров |

## 9. API, которое ожидает фронт (черновик для бэкенда)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/chat/messages` | Сообщение в чат; ответ асинхронно через поток событий |
| GET | `/api/questions?status=` | Мои вопросы / входящие по роли |
| POST | `/api/questions/{id}/confirm-send` | Стажёр подтвердил отправку (`urgent`, правленый текст) |
| POST | `/api/questions/{id}/answer` | Ответ текстом |
| POST | `/api/questions/{id}/redirect` | «Не ко мне» или переадресация бадди |
| POST | `/api/questions/{id}/meeting` | Запрос слотов / выбор слота |
| GET / POST | `/api/kb/pages`, `/api/kb/pages/{id}/approve` | База знаний, подтверждение черновика |
| GET / POST | `/api/plans/{internId}`, `/api/plans/{id}/approve` | План адаптации |
| PATCH | `/api/plan-steps/{id}` | Отметить шаг |
| POST | `/api/requests`, `/api/requests/{id}/confirm` | Заявки (отгул) |
| GET | `/api/dashboard/team` | Реализован: обзор только своих стажёров, прогресс, просрочки, счётчики вопросов и заявки; контракт в [SDD](../spec/05-tools-api.md#обзор-команды-sc-21) |
| GET / POST | `/api/kb/maintenance`, `/api/kb/merge-proposals/{id}/resolve` | Поддержка базы |
| POST | `/api/notifications/telegram/link` | Одноразовый код для Telegram |
| GET | `/api/events/stream` | Поток событий (SSE / WebSocket) |

## 10. Маскот-виджет: технические требования

- Отдельный компонент поверх контента, позиция по умолчанию — правый нижний угол, отступ 24 px.
- Размер 96×96 px развёрнутый, 32×32 px свёрнутый до точки.
- Перетаскивается мышью; позиция и состояние «свёрнут / скрыт» сохраняются для пользователя.
- Состояния и переходы — машина состояний из [08-DESIGN.md](./08-DESIGN.md), события приходят из потока `/api/events/stream`.
- Анимации на CSS / Lottie / Rive или спрайтах — на выбор команды; лёгкие (≤ 300 КБ на набор), без влияния на отклик интерфейса.
- Клик — открыть или закрыть чат; наведение — подсказка (ближайшее событие или «ответ готов»).
- Не перекрывает кнопки и поля: если под виджетом интерактивный элемент, виджет смещается (BR-92).
