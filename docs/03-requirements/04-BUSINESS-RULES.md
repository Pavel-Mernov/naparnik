# 04. Бизнес-правила и ограничения

> Нумерация по группам: 0x — ответы, 1x — маршрутизация, 2x — сводки и срочность, 3x — база знаний, 4x — права и действия, 5x — Telegram, 6x — границы, 7x — нефункциональные, 8x — план адаптации и знания под роль, 9x — маскот, 10x — практика перед задачей.
> Значения в **[квадратных скобках]** — настраиваемые параметры с дефолтом для MVP. Все они вынесены в конфиг отдела, не в код.

## 0x. Ответы ИИ

| ID | Правило |
|---|---|
| BR-01 | Каждый ответ из базы содержит ссылку на источник, дату последнего изменения и автора. Ответ без источника не выдаётся |
| BR-02 | Источники ответа — только опубликованные страницы (`Published`) и документы пространства команды. Черновики и чужие пространства не используются |
| BR-03 | Стажёр может отметить ответ «не помогло» или «устарело». «Не помогло» запускает поиск человека (P1). «Устарело» дополнительно попадает в «Поддержку базы» владельцу |
| BR-04 | Если уверенного ответа нет, ИИ говорит «не нашёл» и предлагает спросить человека. Выдумывать ответ запрещено |
| BR-05 | Синтетические инструкции помечены «тестовая инструкция, не регламент Авито» в ответе и на странице |
| BR-06 | ИИ обращается к стажёру на «ты», к экспертам и руководителю в сообщениях от имени системы — на «вы». Тон — в [08-DESIGN.md](./08-DESIGN.md) |

## 1x. Маршрутизация вопроса

| ID | Правило |
|---|---|
| BR-10 | Кандидат в эксперты выбирается по сигналам: авторство и правки страниц по теме вопроса (вес выше у свежих и у нескольких страниц), зона ответственности в справочнике команды, ответы на похожие вопросы. Кандидат должен быть в команде стажёра или в доступном ему пространстве |
| BR-10a | Руководители уровня **[«руководитель руководителей» и выше: директора, руководители направлений]** не предлагаются стажёру как эксперты напрямую, даже если они авторы страниц по теме. Если лучший кандидат — такой руководитель, вопрос уходит **бадди стажёра** с подсказкой «по теме больше всех писал {имя, роль}». Бадди отвечает сам или переадресует (в том числе этому руководителю, если считает нужным); кнопки «не ко мне» у бадди в этом случае нет. Стажёр видит, что вопрос ушёл бадди, имя руководителя ему не показывается. Уровень руководства берётся из справочника команды (атрибут ABAC), порог настраивается в конфиге отдела |
| BR-11 | Ни один вопрос не уходит человеку без явного подтверждения стажёра |
| BR-12 | ИИ показывает стажёру, кого выбрал и почему: роль и причину («автор 3 страниц о витринах DWH, последняя — 2 недели назад») |
| BR-13 | Если уверенность выбора ниже **[порога 0,6]** или кандидатов нет, ИИ предлагает отправить вопрос бадди |
| BR-14 | Сформулированный вопрос содержит: суть, контекст (задача, страница, что уже нашёл и пробовал), ссылки, срочность. Стажёр видит итоговый текст и может его поправить до отправки |
| BR-15 | Бадди всегда видит маршрут каждого вопроса своего стажёра: адресата, тему и статус. Текст вопроса — по настройке видимости стажёра (BR-86) |
| BR-16 | Бадди может переадресовать вопрос другому адресату. Стажёр и прежний адресат получают уведомление |
| BR-17 | Адресат может нажать «не ко мне» и при желании указать, к кому. ИИ предлагает следующего кандидата; если кандидатов нет — бадди |
| BR-18 | SLA ответа: обычный вопрос — **[1 рабочий день]**, срочный — **[2 рабочих часа]**. Не ответил → напоминание адресату; ещё через SLA → бадди с предложением переадресовать |
| BR-19 | Вопросы, направленные экспертам, не попадают бадди во входящие — только в ленту наблюдения. Так ИИ не добавляет бадди нагрузку. Исключение — вопросы по BR-10a и BR-13, где адресат сам бадди |

## 2x. Сводки и срочные вопросы

| ID | Правило |
|---|---|
| BR-20 | Обычные вопросы приходят получателю сводкой **[2 раза в день: 11:00 и 16:00 по его времени]**. Получатель может выбрать в настройках «сразу» |
| BR-21 | Срочный вопрос («блокирует работу») уходит сразу. У получателя он помечен «Срочно» в вебе, в сводке и в Telegram |
| BR-22 | Перед пометкой «срочно» ИИ уточняет у стажёра: «Без ответа ты не можешь продолжить работу?». Количество срочных вопросов видно бадди |
| BR-23 | Пустая сводка не отправляется |
| BR-24 | В сводке вопросы сгруппированы по стажёрам; у каждого — суть, контекст и кнопки «ответить», «встреча», «не ко мне» |

## 3x. База знаний

| ID | Правило |
|---|---|
| BR-30 | Страница публикуется только после подтверждения автора ответа. ИИ — не автор: автором указан человек, который ответил |
| BR-31 | Любой ответ человека, даже короткий, оформляется страницей типа «Вопрос-ответ» |
| BR-32 | Каждая страница лежит в папке. ИИ предлагает папку и проверяет похожие страницы; если похожая есть — предлагает дополнить её вместо новой |
| BR-33 | Автор не подтвердил черновик за **[3 рабочих дня]** → одно напоминание; ещё через 3 дня черновик уходит в «Поддержку базы» владельцу |
| BR-34 | Владелец базы по умолчанию — руководитель отдела. Он может назначить другого сотрудника |
| BR-35 | Запись встречи включает человек. ИИ напоминает организатору **[за 5 минут]** до начала и в момент начала |
| BR-36 | Из транскрипта в базу попадает только ответ на исходный вопрос с таймкодами, а не пересказ всей встречи. Полный транскрипт и запись доступны только участникам встречи |
| BR-37 | Записи нет → ИИ один раз предлагает адресату ответить текстом. Отказ → вопрос получает статус `Open` и попадает в «Открытые вопросы» владельцу |
| BR-38 | Поиск дублей запускается ИИ-кроном раз в **[4 месяца]**. Владелец получает сводку: пары похожих страниц с предложенным объединённым текстом и открытые вопросы |
| BR-39 | Объединение только с подтверждения владельца. Старые страницы получают статус `Merged` и ведут на новую. Авторы получают уведомление. Пара «не дубль» больше не предлагается |

## 4x. Права и действия

| ID | Правило |
|---|---|
| BR-40 | Права проверяются до вызова любого инструмента ИИ (поиск, чтение страницы, действие). Недоступное не показывается, не цитируется и не упоминается |
| BR-41 | Встреча создаётся только после подтверждения адресата, слоты — только в рабочие часы обоих участников |
| BR-42 | Для заявок ИИ предлагает два пути: «сделай сам» (шаги и ссылка) или «сделаю за тебя» |
| BR-43 | Любое действие идёт по лестнице доверия: черновик → подтверждение → выполнение → квитанция. Квитанция сохраняется в истории и ленте |
| BR-44 | Нет прав на операцию → ИИ объясняет причину и предлагает подготовить запрос тому, у кого право есть |
| BR-45 | Нет доступа к системе или данным, которые нужны стажёру → ИИ называет систему из каталога сервиса доступов, на какой неделе её по плану нужно запросить (`week_from`) и кто согласует, и предлагает заявку: «сделай сам» или «сделаю за тебя» (BR-42). Закрытые страницы, их названия и авторы при этом не называются (BR-40). Системы с грифом ПДн стажёру не предлагаются |
| BR-46 | Поиск и чтение выполняются от имени пользователя: права наследуются из источника (база знаний, трекер, сервис доступов), результаты фильтруются по правам **до** передачи в LLM |
| BR-47 | Права зависят от атрибутов (отдел, роль, проект, гриф данных — допущение, [02-ROLES.md](./02-ROLES.md#6-модель-доступа-rbac-и-abac)). У стажёра те же права, что у команды ([вводные Авито](../01-discovery/avito-inputs.md)); неделя стажировки права не ограничивает, а задаёт срок запроса по плану. Кэш прав живёт не дольше **[15 минут]** |
| BR-48 | Каждое действие от имени стажёра (заявка, вопрос человеку, встреча) пишется в журнал: кто, что, когда, через какой сервис, результат |
| BR-49 | Гриф данных сохраняется. Во внешнюю LLM не передаются ПДн, секреты и конфиденциальные данные (стратегия, финансы, планы запусков) — они фильтруются по грифу до запроса, как и по правам (BR-46). Страница базы из ответа или встречи получает самый закрытый гриф среди источников и видна не шире их. В MVP на синтетических данных — требование к внедрению ([11-INTEGRATION.md](./11-INTEGRATION.md)) |

## 5x. Telegram

| ID | Правило |
|---|---|
| BR-50 | Telegram подключается по желанию пользователя через одноразовый код в настройках |
| BR-51 | В Telegram приходят только уведомления без содержания: тип события, имя, ссылка в веб. Тексты вопросов, ответов и страниц не отправляются |
| BR-52 | Уведомления в Telegram подчиняются рабочим часам и режиму «не беспокоить»; срочные приходят в рабочие часы сразу |
| BR-53 | Недоступность Telegram не влияет на работу веба; уведомление остаётся в вебе |

Типы уведомлений в Telegram: ответ на твой вопрос, тебе назначили встречу, напоминание о событии или дедлайне, черновик страницы ждёт проверки, новый срочный вопрос, сводка вопросов готова, статус заявки изменился.

## 6x. Границы

| ID | Правило |
|---|---|
| BR-60 | ИИ не оценивает стажёра и не отвечает по существу на вопросы об оценке, выходе в штат, зарплате и конфликтах — предлагает обсудить с бадди или руководителем |
| BR-61 | Сценарии с чувствительными ПДн и финансовыми операциями не поддерживаются |
| BR-62 | При знакомстве с командой ИИ рассказывает, кто есть кто, и готовит черновик сообщения, но не пишет коллегам от имени стажёра |
| BR-63 | Все данные синтетические; реальные данные сотрудников не используются |

## 7x. Нефункциональные

| ID | Правило |
|---|---|
| BR-70 | Обращения к LLM и внешним сервисам не блокируют интерфейс: статус ожидания, таймаут **[30 с]**, понятная ошибка, «повторить», запрос не теряется |
| BR-71 | Локальные операции интерфейса — быстрее 1 с |
| BR-72 | В LLM не передаются ПДн и секреты; ключ — через переменную окружения |
| BR-73 | Каждое действие ИИ и людей логируется как событие для метрик ([09-METRICS.md](./09-METRICS.md)) |
| BR-74 | Интеграции — через адаптеры с единым интерфейсом; замена Jira, Confluence, календаря или сервиса отсутствий не меняет логику агента |

## 8x. План адаптации и ведение

| ID | Правило |
|---|---|
| BR-80 | Шаблон плана — данные отдела (этапы и шаги по неделям на основе чек-листа Авито). Логика не зависит от отдела |
| BR-81 | ИИ готовит черновик плана → бадди правит → руководитель утверждает. Нет решения **[2 рабочих дня]** → план активируется по шаблону с пометкой «не утверждён» |
| BR-82 | Шаг плана = подзадача эпика адаптации в трекере. Прогресс читается из статусов трекера |
| BR-83 | Режимы проактивности стажёра: «план на день» (по умолчанию), «только дедлайны и встречи», «выкл» |
| BR-84 | Напоминания: утренний дайджест, **[за день и за час]** до события, риск по дедлайну. Только в рабочие часы |
| BR-85 | Нет активности **[2 рабочих дня]** → мягкий сигнал бадди «простаивает» |
| BR-86 | Видимость для бадди: текст вопросов стажёра виден бадди по умолчанию; стажёр может отключить. Адресат и статус видны всегда (нужны для переадресации) |
| BR-87 | Набор знаний — данные роли, а не код: для каждой роли (аналитик, бэкенд, фронтенд, QA) отдел задаёт свои папки базы, глоссарий, код-стайл, карту данных или сервисов и учебные задания. Логика ИИ от роли не зависит. В MVP заполнен набор аналитика, для бэкенда — пример |
| BR-88 | Жаргон команды отвечается из глоссария отдела с пометкой «у нас так говорят»; общий смысл термина ИИ может дать и без базы, но с пометкой «общее определение». Нового термина нет в глоссарии → ИИ предлагает добавить его, подтверждает бадди |

## 9x. Маскот

| ID | Правило |
|---|---|
| BR-90 | Маскот привлекает внимание только по поводу: пришёл ответ, скоро событие, черновик ждёт подтверждения, новый шаг плана. Без повода — никаких подсказок |
| BR-91 | Маскот засыпает после **[3 минут]** без взаимодействия и просыпается по клику, наведению или событию _(вне прототипа — следующий шаг)_ |
| BR-92 | Маскот не перекрывает элементы интерфейса; его можно перетащить, свернуть до точки и скрыть |
| BR-93 | Состояние маскота дублируется текстом или бейджем; при `prefers-reduced-motion` анимации заменяются статичными кадрами |

## 10x. Практика перед задачей

| ID | Правило |
|---|---|
| BR-100 | Перед шагом плана типа `task` или `study`, у которого в шаблоне есть сценарий практики, ИИ предлагает пройти практику. Практика необязательна: стажёр может сразу перейти к задаче |
| BR-101 | Порядок практики: (1) общепринятые термины → (2) термины и правила команды → (3) учебное задание по желанию → (4) переход к реальной задаче с чек-листом и ссылками. Каждый шаг можно пропустить |
| BR-102 | Учебное задание ИИ генерирует по шаблону практики и страницам базы; до показа стажёру его одобряет или правит бадди. Нет решения **[1 рабочий день]** → стажёр видит практику без учебного задания |
| BR-103 | Учебное задание выполняется только на синтетических данных или в песочнице; продовые дашборды и витрины в нём не используются |
| BR-104 | ИИ проверяет попытку по критериям задания и даёт обратную связь со ссылками на страницы базы. Готового решения реальной задачи ИИ не выдаёт |
| BR-105 | Бадди видит лучшую попытку, число попыток и темы, где были ошибки. Черновые попытки и диалог стажёра с ИИ бадди не видит |
| BR-106 | Попыток не больше **[3]**; после третьей неудачной ИИ предлагает спросить бадди по P1 с контекстом задания |
