## Ключевые решения

| Решение | Почему |
|---|---|
| Своё веб-приложение с интерфейсами для всех ролей, интеграции через адаптеры | Доступа к внутренним системам нет; адаптеры позволяют подключить Jira, Confluence, календарь без изменения логики |
| Эксперт выбирается по авторству страниц, с объяснением причины | Стажёр «не знает, кого спросить»; объяснение повышает доверие и даёт бадди поправить ошибку |
| Бадди видит маршруты всех вопросов, но вопросы экспертам не попадают к нему во входящие | Бадди хочет видеть, как стажёр работает с командой, но не хочет лишней нагрузки |
| Обычные вопросы — сводкой 2 раза в день, срочные — сразу с пометкой | Бадди и эксперты не хотят, чтобы помощь разрывала их работу; срочное не ждёт |
| Любой ответ, даже короткий, становится страницей; раз в 4 месяца — объединение дублей | База растёт с каждым стажёром и не зарастает дублями |
| Запись встречи включает человек, ИИ напоминает; без записи — ответ текстом или открытый вопрос | Реалистично для MVP; негативный сценарий не теряет вопрос |
| Telegram только для уведомлений, без содержания | Человек узнаёт об ответе вне ноутбука, корпоративные данные не уходят в мессенджер |
| ИИ знакомит с командой, но пишет коллегам сам стажёр | ИИ ведёт стажёра, а не общается вместо него |
| Руководитель мониторит и утверждает план | Оба бадди ждут от руководителя плана и учёта их времени |
| Маскот в MVP — виджет в вебе; поверх всех окон — следующий шаг | Достаточно для демо, без отдельного десктоп-приложения |
| Права на данные не копируем, а наследуем из источников; закрытое не называем | В Авито RBAC + ABAC; утечка названий закрытых страниц — тоже утечка |
| Практика перед задачей необязательна, учебное задание одобряет бадди | Из фидбека Авито: стажёры не знают код-стайл и жаргон; бадди не хотят придумывать задания (Б2), но хотят контролировать содержание |
| Набор знаний — данные роли; демо на аналитике | Кейс не только про бэкенд: показываем другую роль, логика одна |
| Заявки — только отправка в существующие сервисы Авито через адаптер | Свою систему заявок не строим |

**Отличия от IDEA-AND-FLOWS.md:** вместо работы «внутри корпоративных систем» — своё веб-приложение с адаптерами; маршрутизация по авторству страниц вместо «по роли»; согласие на запись заменено напоминанием включить запись; добавлены роль эксперта, сводки, Telegram и плановая чистка базы; куратор вынесен за MVP.

## Глоссарий

| Термин | Значение |
|---|---|
| Бадди | Наставник, закреплённый за стажёром |
| Эксперт | Сотрудник команды, которому ИИ направил вопрос как вероятному знатоку темы |
| Владелец базы | Отвечает за актуальность базы знаний отдела; по умолчанию руководитель |
| Маршрут вопроса | Цепочка адресатов вопроса, видимая бадди |
| Сводка | Пакет обычных вопросов, который получатель получает по расписанию |
| Поддержка базы | Раздел владельца: открытые вопросы, неподтверждённые черновики, устаревшее, дубли |
| Лестница доверия | Черновик → подтверждение → выполнение → квитанция |
| Адаптер | Модуль интеграции с внешней системой с единым интерфейсом; в MVP работает с заглушкой |
| ИИ-крон | Планировщик: сводки, напоминания, плановая проверка базы |
| Практика | Необязательный разбор перед шагом плана: общие термины → термины команды → учебное задание → реальная задача (P7) |
| Учебное задание | Задание на синтетических данных или в песочнице; генерирует ИИ, одобряет бадди |
| Набор знаний роли | Глоссарий, код-стайл, карта данных или сервисов и учебные задания для конкретной роли стажёра |
| ABAC | Доступ по атрибутам: отдел, роль, статус и неделя стажёра, проект, гриф данных (допущение) |
