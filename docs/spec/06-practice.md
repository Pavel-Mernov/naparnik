# Практика перед задачей (P7, SC-30…SC-32)

Практика необязательна и не отмечает реальную задачу выполненной. Шаблон и критерии — `practice.json`; примеры одобрения и попыток из этого файла не импортируются как результаты пользователя.

## API

Авторизация — существующий `X-User`. Стажёр видит только собственную практику, бадди — закреплённых стажёров. Руководитель, эксперт и чужой стажёр получают 403. Все ответы — `{ok, data}`.

| Метод | Путь | Действие |
|---|---|---|
| GET | `/api/practices` | Доступные практики с учётом роли |
| POST | `/api/practices/sync` | Подготовить недостающие черновики по шагам утверждённых планов; генерация вне транзакции БД |
| POST | `/api/practices/{intern}/{practice}/generate` | Бадди повторяет неудавшуюся генерацию черновика |
| POST | `/api/practices/{intern}/{practice}/approve` | Бадди правит текст и одобряет: `{text, task_version}` |
| POST | `/api/practices/{intern}/{practice}/advance` | Стажёр: `{action: start|next|skip_stage|skip_all, expected_stage}` |
| POST | `/api/practices/{intern}/{practice}/attempts` | Стажёр: `{answer, task_version}` + обязательный `Idempotency-Key` |
| POST | `/api/practices/{intern}/{practice}/help-draft` | После трёх неудач — черновик вопроса своему бадди, отправка через существующее подтверждение |

Этапы: `offered → general_terms → team_terms → training → real_task`. Пропуск этапа разрешён, пропуск всей практики сразу открывает чек-лист. Без одобрения за один рабочий день стажёр продолжает без задания; черновик остаётся у бадди. Дедлайн вычисляется по календарю рабочих дней (в MVP — пн–пт) и демо-дате сервера, не дате браузера.

Генератор получает шаблон, синтетическое окружение и только доступные опубликованные источники. Проверяющий получает учебное задание, критерии, доступные источники и текущую попытку; диалог и реальная задача ему не передаются. SQL и код пользователя не исполняются. Результат LLM валидируется по числу и номерам критериев; итог и лучшую попытку выбирает код. При недоступности LLM попытка не расходуется. В заглушке используется статическая проверка учебного SQL по типам критериев из шаблона.

Повтор отправки попытки с тем же ключом возвращает сохранённый результат; другое тело — 422. После проверки вне БД транзакция заново проверяет владельца, версию задания, этап и лимит (3). Бадди получает только лучшую попытку, число попыток и объединённые темы ошибок; остальные ответы и обратная связь в его DTO отсутствуют.

Состояние и события практики входят в JSONB-снимок версии 2. Снимок версии 1 без полей практики читается как пустая практика; при следующей записи сохраняется версия 2. Старый backend откажется читать версию 2, чтобы не стереть новые поля своей записью. При подготовке практики недостающие опубликованные страницы, на которые ссылается её шаблон, добавляются из конфигурации; существующие страницы и пользовательские объекты не перезаписываются. Общая миграция справочников и наборы знаний других профессий в эту задачу не входят.
