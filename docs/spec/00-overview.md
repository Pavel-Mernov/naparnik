## Архитектура

```
Фронт ──HTTP──► backend (Go)
                 ├─ httpapi     — API для фронта (07-FRONTEND, раздел 9), учётка в заголовке X-User
                 ├─ agent       — цикл агента, защита до модели, черновики, запасной ответ
                 ├─ tools       — инструменты с проверкой прав в коде
                 ├─ llm         — провайдеры: Claude (anthropic-sdk-go), DeepSeek (openai-go), заглушка
                 ├─ store       — состояние (план, заявки, вопросы); сейчас в памяти
                 └─ mockdata    — читает docs/04-mock-data как есть
```

- **Модель выбирает, код решает.** Модель выбирает инструмент и параметры; права, проверки и выполнение — в коде.
- **Лестница доверия (BR-43).** Инструменты, которые что-то создают или отправляют людям, превращаются в черновик; выполняются только по подтверждению человека (`POST /api/requests/{id}/confirm`, `/api/questions/{id}/confirm-send`).
- **Адаптеры (BR-74).** Сервисы отсутствий, доступов, база знаний и трекер сейчас — мок-данные команды. Замена на реальные системы меняет `store` и `tools`, но не агента. Следующий шаг — оформить инструменты как MCP-сервер.

## Покрытие требований

| Требование | Где |
|---|---|
| BR-01, BR-02, BR-04, BR-05 — ответ с источником, только своё пространство, «не нашёл», пометка тестовой инструкции | `tools.SearchKB`, порог `MinCoverage` |
| BR-10…BR-13 — подбор эксперта, причина, порог 0,6, иначе бадди | `tools.FindExpert`, `ExpertThreshold` |
| BR-11, BR-43 — ничего не уходит без подтверждения | `agent.handle` → черновик, `agent.Confirm` |
| BR-40, BR-44 — права до вызова, недоступное не предлагается даже черновиком | `tools.Run`, `tools.Check` |
| BR-42 — «сделай сам» или «сделаю за тебя» | `get_absence_rules` (self_service) |
| BR-60, BR-61, BR-72 — границы и ПДн обрабатываются до модели, в LLM не уходят | `agent.guard`, `MaskPII` |
| BR-70 — модель недоступна или молчит: запасной ответ, «повторить» | `agent.fallback`, режимы `LLM_MODE` |
| BR-86, 02-ROLES — видимость вопросов для бадди и руководителя | `httpapi.questions` |
| Покрытие тестами > 80 % | `go test ./... -coverprofile`; в CI проверяется порог |

## Известные ограничения

- Подбор эксперта — лексический (совпадение слов + свежесть + зона ответственности). Лидер верный на Q2, Q3, Q5, Q11, но уверенность у Q2 и Q5 ниже порога → уйдут бадди. Настраивать на `docs/04-mock-data/evals.json`.
- Не реализованы: ответы людей и черновики страниц (P2), встречи и транскрипты (P3), дашборд руководителя, поддержка базы (P5), сводки и Telegram, поток событий SSE. Состояние в памяти — сбрасывается при перезапуске.
