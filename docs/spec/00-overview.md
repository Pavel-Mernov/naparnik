## Архитектура

```
Фронт ──HTTP──► backend (Go)                                MCP-клиент ──stdio──► cmd/mcp
                 ├─ httpapi     — API для фронта, учётка в заголовке X-User              │
                 ├─ agent       — цикл агента, защита до модели, страховки после неё, черновики
                 ├─ tools       — инструменты с проверкой прав в коде ◄──────────────────┘
                 ├─ adapters    — интерфейсы сервисов: отсутствия, доступы, календарь (мок / HTTP); выгрузка событий
                 ├─ flags       — feature flags (FEATURE_FLAGS, FLAGS_FILE)
                 ├─ llm         — провайдеры: Claude (anthropic-sdk-go), DeepSeek (openai-go), заглушка
                 ├─ store       — состояние, журнал событий, уведомления, сторожа сроков; PostgreSQL (или память)
                 ├─ cache       — Redis (или память): коды и копии привязок Telegram, лимит модели, блокировки, кэш поиска
                 ├─ telegram    — бот: привязка, доставка, напоминания; планировщик раз в 15 с
                 ├─ evals       — прогон эталонного набора evals.json через агента (cmd/evals)
                 └─ mockdata    — читает docs/04-mock-data как есть
```

- **Модель выбирает, код решает.** Модель выбирает инструмент и параметры; права, проверки и выполнение — в коде.
- **Лестница доверия (BR-43).** Инструменты, которые что-то создают или отправляют людям, превращаются в черновик; выполняются только по подтверждению человека (`POST /api/requests/{id}/confirm`, `/api/questions/{id}/confirm-send`).
- **Код страхует модель.** Что можно проверить без модели, проверяет код: права и ПДн — до модели; источник, пометка тестовой инструкции, честное «в базе нет», имя эксперта — после ответа модели ([04](04-agent-behavior.md#страховки-после-модели)).
- **Адаптеры (BR-74).** Сервисы отсутствий, доступов, база знаний и трекер сейчас — мок-данные команды. Инструменты работают через интерфейсы `adapters`: настоящая система — новая реализация интерфейса ([09](09-adapters.md)), агент и права не меняются. Сервис отсутствий уже подключается по REST (`ABSENCE_SERVICE_URL`). Те же инструменты доступны как MCP-сервер ([08](08-mcp.md)).

## Известные ограничения

- Подбор эксперта и поиск — лексические (основы слов, синонимы отдела, IDF, свежесть, зона ответственности), без эмбеддингов. Качество держится на эталонном наборе: DeepSeek — 43 из 43 ([docs/evals](../evals/live.md)); новый вопрос мимо словаря может уйти бадди — это безопасное направление ошибки (BR-13).
- Сессия модели (история разговора) — в памяти процесса, после перезапуска начинается заново; состояние, черновики и квитанции — в PostgreSQL. См. [PERSISTENCE](../PERSISTENCE.md).
- Живые обновления реализованы через SSE (`GET /api/stream`): сервер проверяет изменения данных пользователя каждые 2 с и отправляет `changed`; при обрыве соединения веб продолжает резервный опрос раз в 30 с. Источник: `backend/internal/httpapi/stream.go`.
- MCP — только stdio-транспорт.
- Решения по заявкам из настоящего сервиса отсутствий подтягиваются опросом `GET /requests/{id}` (`ABSENCE_SYNC_SEC`); вебхука нет. Для сервиса доступов синхронизации нет — он имитация.

Полный цикл плана адаптации: [редакции и согласование](10-plan-lifecycle.md). Приёмка собранного приложения: [ACCEPTANCE](../ACCEPTANCE.md).
