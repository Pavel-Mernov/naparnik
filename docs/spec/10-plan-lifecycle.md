# План адаптации: редакции и согласование

Реализует SC-20, SCR-L2, US-09 и BR-81. HTTP-слой разбирает запрос, `tools` проверяет роль и версию внутри транзакции; `store` сохраняет состояние, историю и задачи в PostgreSQL.

## Состояния и права

`status` описывает **действующий** план: `draft` (ещё нет активного), `approved`, `auto_activated`.
`review_status` описывает **согласуемую редакцию**: `editing`, `review`, `returned`; пустая строка — новой редакции нет.

- Первый шаблон уже находится в `review`: руководитель может утвердить его или вернуть с обязательным замечанием. Бадди может сохранить правки — это переводит редакцию в `editing`; затем требуется отдельное «Отправить на согласование».
- Возврат в `returned` останавливает автоактивацию. Бадди дорабатывает и повторно отправляет редакцию. Замечание руководителя сохраняется отдельно от комментария бадди и остаётся в истории.
- Без решения по первому отправленному плану за два рабочих дня руководителя он активируется как `auto_activated`. Срок считается от `submitted_at` (у прежнего шаблона — `created_at`); новая отправка запускает срок заново. Во время доработки таймер не идёт.
- У действующего плана бадди начинает новую редакцию. Руководитель также может запросить доработку действующего плана через возврат с комментарием. Пока изменения не утверждены, стажёр работает по прежней редакции.
- Новые редакции действующего плана **не применяются автоматически**. Бадди может отменить такую редакцию; отмена и её снимок остаются в истории. Первый план отменить нельзя.
- Руководитель утверждает только отправленную редакцию. Бадди не утверждает, руководитель не редактирует шаги, эксперт не получает карточку чужого плана.

## Версии и история

`version` — версия всей карточки. Каждая мутация передаёт её явно; устаревшая версия возвращает `409 conflict` без изменений, событий и уведомлений. В интерфейсе после конфликта загружается актуальное состояние. Запрос без положительной версии — `422`.

`revision` — номер последней начатой редакции; `active_revision` — номер применённой. После отмены номера не используются повторно.

История содержит действие, автора, время, комментарий, снимок шагов и разницу сроков/состава. Она добавляется только в HTTP-ответ человеку; инструмент `get_plan` не передаёт модели комментарии и повторяющиеся снимки. События журнала аналитики содержат действие и номера версий, без комментариев. Бадди и руководитель видят всю историю своего стажёра; стажёр — только применённые редакции. Старые снимки JSONB версии 1–3 автоматически получают версию плана 1 и исходную запись истории; недоступные прошлые правки не выдумываются. При миграции задачи и квитанции сохраняются.

## Применение правок

Сроки — рабочие дни, шаги — из существующего шаблона. Можно убрать или вернуть шаг, назначить ему срок; остаётся хотя бы один шаг стажёра. Для изменения действующего плана требуется комментарий с причиной, до 2000 символов.

Статусы `Done`, номера задач и квитанции сохраняются. Выполненный шаг нельзя убрать или перенести. Проверка повторяется **при утверждении**: если стажёр завершил изменяемый шаг во время согласования, руководитель получает конфликт и возвращает редакцию на доработку. До коммита новой редакции состав, сроки и прогресс действующего плана не меняются. Карточка содержит каждый шаг шаблона один раз, включая помеченные как убранные.

## API

Все записи принимают `{ "version": N }`; отдельный `Idempotency-Key` не требуется: повтор устаревшей мутации даёт конфликт и не создаёт второе решение.

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/plans/{internId}/draft` | Карточка редакции, возможности `can_*`, история и разница; бадди/руководитель |
| PATCH | `/api/plans/{internId}/draft` | `{version, steps: [{step_id, due_date?, removed?}], comment}` — сохранить правки, без отправки |
| POST | `/api/plans/{internId}/revisions/start` | Начать редакцию действующего плана; бадди |
| POST | `/api/plans/{internId}/revisions/submit` | Отправить или повторно отправить на согласование; бадди |
| POST | `/api/plans/{internId}/revisions/return` | `{version, comment}` — вернуть с замечанием; руководитель |
| POST | `/api/plans/{internId}/revisions/cancel` | Отменить редакцию действующего плана; бадди |
| POST | `/api/plans/{internId}/approve` | Утвердить отправленную редакцию или первый автоактивированный план |
| GET | `/api/plans/{internId}/history` | История с проверкой доступа; стажёру только применённые редакции |
| GET | `/api/plans/{internId}` | Действующий план с `plan_revision`, `plan_history`; бадди/руководителю также `review_status` |
