# 03. Сценарии

PDF стр. 7: «сосредоточьтесь на 3–5 сценариях либо на одном глубоко проработанном». Стр. 11, пункт 08: количество сценариев не влияет на оценку, важно, чтобы **весь заявленный функционал работал**.

Решение: **один глубокий путь** (Backend-стажёр Артём, 3 роли), внутри которого 4 сценария кейса, плюс **короткие демо** других отделов. Каждый критерий приёмки = автотест.

Обозначения статуса реализации: **[ядро]** — обязательно; **[заглушка]** — работает на фикстурах, это заявляется явно.

## Глубокий путь: «Вторая неделя Артёма» (Backend)

### С1. Маршрут по чек-листу [ядро]
PDF: постановка 01, 04.

1. 09:30 бот в Telegram и на сайте присылает **шаги на сегодня** (1–3 штуки) по текущему периоду чек-листа: «Неделя 2: запроси доступ в пространство юнита; изучи документацию по работе с БД; расскажи о Observer».
2. Первый шаг уже подготовлен: черновик заявки на доступ (→ С4).
3. Сайт показывает маршрут: этапы (неделя 1, неделя 2, месяц 1, месяц 2–3, экватор), статусы шагов, **следующий шаг**, просроченное, блокеры.
4. Вечером непройденные шаги переносятся на завтра; если шаг висит > 2 дней — бот спрашивает «помочь?» и предлагает спросить наставника (→ С3).

Критерии приёмки:
- шаги на сегодня берутся только из текущего и просроченных периодов, не больше 3;
- шаги с `owner = mentor` стажёру не показываются как его задачи;
- статус шага меняется только по действию стажёра или наставника, агент лишь предлагает;
- прогресс этапа = выполненные / все шаги этапа; одинаковый на сайте, в Telegram и у наставника.

### С2. Вопрос, ответ есть в базе [ядро]
PDF: постановка 02.

1. Артём: «что такое Шаталити?» (на сайте или в Telegram).
2. Агент ищет в базе знаний **отдела Backend**, отвечает кратко и даёт **источник, дату и кто подтвердил**.
3. Кнопки «Помогло» / «Не помогло». «Не помогло» → С3.

Критерии приёмки:
- в ответе есть хотя бы одна ссылка на источник из базы; без источника ответ не показывается;
- если источник — демо-документ, в ответе пометка «демо-регламент»;
- вопрос **не появляется** у наставника (см. 01, главный принцип видимости);
- термины из глоссария подсвечиваются и объясняются по нажатию.

### С3. Вопрос, ответа нет → вопрос человеку [ядро]
PDF: постановка 02; стр. 6 — наставник отвечает на вопросы, требующие участия коллег; стр. 4 — не заменяя личного общения.

1. Артём: «как задеплоить сервис на стейдж через PaaS?» — в базе нет ответа (или С2 «не помогло», или застрял на шаге > 2 дней).
2. Агент **формулирует вопрос**: суть, контекст (шаг маршрута, неделя), что уже пробовал.
3. Агент выбирает адресата по теме: наставник (Олег) / владелец сервиса (Павел) / руководитель (Ирина). Показывает черновик и адресата.
4. Артём правит и подтверждает. Можно отметить «без имени» — тогда наставник видит вопрос без автора.
5. Адресат получает уведомление (сайт + Telegram), отвечает текстом **или** выбирает «обсудим на встрече» (→ С3а).
6. Ответ приходит Артёму. Агент предлагает автору сохранить ответ в базу; после подтверждения автора ответ попадает в базу с его именем.
7. Нина (второй стажёр) задаёт тот же вопрос → получает ответ сразу (С2).

Критерии приёмки:
- без подтверждения стажёра вопрос никуда не уходит;
- в базу ответ попадает только после подтверждения автора, с автором и датой;
- анонимный вопрос не содержит идентификаторов автора в данных, которые видит наставник;
- повторный вопрос другого стажёра после сохранения закрывается без наставника (метрика «повторные вопросы»).

### С3а. Ответ через встречу и расшифровку [заглушка]
PDF: усилитель наставника, не замена (стр. 5).

1. Наставник выбирает «обсудим на встрече» → агент предлагает 3 слота из календарей (имитация) → встреча создана, вопрос прикреплён к приглашению.
2. После встречи — **расшифровка из фикстуры** (заранее подготовленный транскрипт), агент выделяет фрагмент с ответом и таймкод.
3. Наставник проверяет выжимку → подтверждает или правит → ответ в базе со ссылкой «запись, 12:40».

Критерии приёмки: без подтверждения наставника выжимка не попадает в базу; в интерфейсе явно указано, что расшифровка — демо-фикстура.

### С4. Действие через сервис: отгул [ядро — обязательное действие кейса]
PDF: пример стр. 4; стр. 11 — действие выполнено, если сервис или имитация возвращает результат, а помощник его отображает и сохраняет.

1. Артём: «мне нужен отгул в пятницу».
2. Агент объясняет порядок (демо-регламент, со ссылкой) и **предпроверяет**: дата не в прошлом, нет пересечения с встречей 1:1 или дедлайном шага; в пятницу релизный поезд? — предупреждение.
3. Черновик заявки: тип, дата, причина (необязательно), согласующий (руководитель Ирина).
4. Артём подтверждает → заявка уходит в **имитацию сервиса отсутствий** → квитанция: номер, статус «на согласовании», кто согласует. Квитанция видна в чате, в ленте и в «Моих заявках».
5. Ирина в кабинете руководителя (или кнопкой в Telegram) согласует / отклоняет **с кодом причины**.
6. Артём получает уведомление со статусом (сайт + Telegram); при отказе — причина человеческим языком и предложение другой даты.

Альтернативы: нет прав → объяснение и запрос тому, у кого право есть; сервис недоступен → понятная ошибка, черновик сохранён, «повторить»; LLM медленная → статус «думаю…», интерфейс не блокируется.

Критерии приёмки:
- заявка создаётся только после явного подтверждения;
- квитанция сохраняется и видна после перезагрузки;
- согласовать может только руководитель этого стажёра; стажёр и наставник — `forbidden`;
- отказ без кода причины невозможен;
- уведомление о смене статуса приходит в оба канала.

### С5. Действие через сервис: доступ [ядро]
PDF: стр. 6 — «получить доступы»; чек-лист: «запроси доступ в пространство своего кластера».

1. Шаг маршрута «запроси доступ к Grafana» → черновик уже готов: система, причина (ссылка на шаг чек-листа).
2. Подтверждение → **имитация сервиса доступов** → квитанция → согласование руководителем → статус «выдан» → шаг маршрута отмечается выполненным автоматически после подтверждения стажёром.
3. Наставник видит статус доступов своего стажёра (это его пункт чек-листа «проверь, запросил ли стажёр доступы»).

Критерии приёмки: те же, что С4; список доступных систем зависит от отдела и недели.

### С6. Права: недоступное [ядро]
PDF: огр. 05.

Артём просит: «покажи заявки Нины» / «согласуй мою заявку сам» / «какие оценки у стажёров?» → агент отказывает, объясняет почему и, где уместно, предлагает к кому обратиться. Вопросы об оценке, выходе в штат, зарплате → «это решает человек», черновик вопроса руководителю.

Критерии приёмки: ни один инструмент не возвращает чужие данные; тесты на каждое правило матрицы из 01.

### С7. Кабинеты наставника и руководителя [сверх кейса, минимально]
PDF: огр. 01 — допустимо, не обязательно.

- **Наставник Олег:** лента прогресса стажёров (этап, %, блокеры), входящие вопросы, выжимки на подтверждение, агрегированные темы вопросов (≥ 3 стажёров), свои пункты чек-листа (добавить в каналы, назначить 1:1, экватор).
- **Руководитель Ирина:** подчинённые и сводка прогресса, заявки на согласование с кодом причины, блокеры > 2 дней.
